# 群存储归属（Groups Storage Ownership）

> 一句话：**群数据的唯一权威存储是 Python 的 `.shadowflow/groups/*.json`**，Node 只做
> 代理、回复生成与归属校验。Node 的 SQLite 两张群表属于**已冻结的实验分支**。

最后核对：2026-11-09。

---

## 1. 谁存什么

| 数据 | 位置 | 归属进程 | 写者 | 读路径 |
|---|---|---|---|---|
| 群记录（名称/成员/策略/模板/公告/归档/用户设置） | `.shadowflow/groups/<group_id>.json` | **Python** | `api/groups/groups.py`（`_save_group` 的 tempfile 原子替换） | Node 经 HTTP `GET /api/groups/:id`；浏览器经网关代理 |
| 群消息（含 reply_to / reactions / pinned / attachments） | 同上，`messages[]` 数组 | **Python** | 同上（`POST /api/groups/:id/messages` 等） | 同上 + SSE 事件总线 |
| 群归属（谁能看这个群） | `.shadowflow/app.sqlite` 的 `resource_owners` | **Node** | `storage/resource-owners.ts` | `middleware/group-access.ts` |
| 群路径下的 run 时间线 | Node 聚合（`lib/gateway-run.ts`、`lib/timeline-replay.ts`），底层事件在 Python 的 `runtime.sqlite` | Node 聚合 / Python 存事件 | — | `GET /api/groups/:id/timeline`（Node 拼装） |
| **（实验分支）**群记录副本 | `app.sqlite` 的 `groups` 表 | Node | `storage/groups-store.ts` | 仅 `SF_GROUPS_BACKEND=node` 时 |
| **（实验分支）**群消息副本 | `app.sqlite` 的 `group_messages` 表 | Node | 同上 | 同上 |

## 2. 为什么 `groups` / `group_messages` 两表是「随 node 分支退役」

- 它们是 2026-06-12「后端合一·阶段1b」为验证「群完全留 Node」做的数据层，与 Python
  JSON 记录逐字段等价（蛇形列名、JSON 文本列）。
- 一旦启用就产生**两份同源数据**，需要 `SF_GROUPS_BACKEND=dual` 做双写 diff 才能发现
  漂移——这本身就违反单一写者原则。
- 2026-11-09 起：`node` / `dual` 两个取值标记为**实验分支，不再维护**，代码保留以便
  回滚；默认路径（未设或 `python`）不挂载 Node 路由、只走 Python。
- 判定与告警集中在 `backend/node/src/lib/groups-mode.ts`（首次进入实验模式会打醒目
  `console.warn`）。启用 `node` 时 `index.ts` 另有一处启动告警。

**结论**：`groups` / `group_messages` 两张表随 node 分支退役；不再为它们加列、不写迁移
（`migrations/002-core-tables.sql` 仅保留建表以兼容历史库）。

## 3. Node → Python 的调用约定（2026-11-09 收敛）

所有 Node → Python 的群持久化请求都走 `backend/node/src/lib/groups-persistence.ts`：

```ts
pythonGroupsFetch(`/${groupId}/messages`, { method: 'POST', body, internal: true })
// → POST {PYTHON}/api/groups/<id>/messages?source=gateway
//   Header: X-SF-No-Dispatch: 1（兼容旧语义，一个版本周期后删除）
```

- `?source=gateway` 是**显式语义**：告诉 Python「这条是网关代写的，别再自己回一条」。
- 旧头 `X-SF-No-Dispatch` 仍兼容：Python 收到会打一条弃用日志，下个版本移除。
- 直接调用 Python（不经网关）的调用方不传这两个标记，保留 Python 自带回复桥作为兜底。

## 4. X-SF-* 头清理清单

| 头 | 定义处 | 谁发 | 谁收 | 处置 |
|---|---|---|---|---|
| `X-SF-No-Dispatch` | `lib/groups-persistence.ts`（`internal: true`） | Node 网关代写群消息 | `api/groups/groups.py` 的 `post_group_message` | **改语义**：新写法用 `?source=gateway`；旧头兼容一个版本周期后废弃 |
| `X-LLM-Key` / `X-LLM-Provider` / `X-LLM-Model` | 前端 `chat-api` / 网关转发 | 浏览器 | `api/groups/groups.py`、`api/groups/chat.py` | **保留**：BYOK 请求级凭据，非内部协议头；无头时已回落到统一配置源（见报告-03） |

> 其余 `X-SF-*` 头（若有新增）一律按「显式 query / 显式 body 字段」优先，头只用于
> 传输层元数据，不承载业务语义。

## 5. 排查入口

- 群读不到 → 先确认 `SF_GROUPS_BACKEND` 未设（设为 `node` 会读 SQLite 而非 JSON）。
- 群回复重复 → 检查是否有调用方漏传 `source=gateway`（Python 桥 + Node 网关同时回）。
- 群归属 404 → 看 `resource_owners` 是否有该 group 的行（`middleware/group-access.ts`）。
