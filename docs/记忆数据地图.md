# 记忆数据地图（Memory Data Map）

> 目的：把「哪份记忆数据存在哪、谁写、谁能读、谁消费」一次说清，杜绝两份数据互相覆盖。
> 划界原则见 §1；数据清单见 §2（Node）/ §3（Python）；交接链路见 §4；双写点处置见 §5。
>
> 最后核对：2026-11-09（对应代码版本：migration 框架落地后）。

---

## 1. 划界原则（单一写者）

| 域 | 归属进程 | 理由 |
|---|---|---|
| **RAG / 知识库**（多模态记忆库、pack、chunk、向量检索） | **Python 专属** | 检索与嵌入在 Python，pack 库文件在 `.shadowflow/knowledge/` |
| **会话记忆 / 经验教训 / Agent 交接 / 长期画像** | **Node 专属** | 与聊天主链路同进程，写入零跨进程开销；表在 `app.sqlite` |
| **跨域读** | 只走 HTTP 公开端点 | Node 读 RAG 走 `lib/memory-bank.ts` → Python `/api/memory-bank/...`；Python 不读 `app.sqlite` |

三条硬约束：

1. **禁止**任何一方直接打开对方的库文件（`.shadowflow/app.sqlite` ↔ `.shadowflow/knowledge/**/memory_bank.sqlite`）。
2. 每份数据有且只有一个写者进程；同进程内也只允许一个模块做写入口（见 §5）。
3. 交接类数据（跨 Agent）的审计流水与内容副本分离：流水进 `agent_hops`，内容进 `memory_handoffs` / `memory_handoff_items`。

---

## 2. Node 侧记忆数据（`.shadowflow/app.sqlite` + 1 个 JSON 文件）

| 数据（表/文件） | 归属进程 | 写者（唯一） | 读端点 | 消费方 |
|---|---|---|---|---|
| `.shadowflow/memory-entries.json` | Node | `storage/memory-entries.ts`（`saveStore` 原子写 tmp→rename） | `GET/POST/PUT/DELETE /api/memory-entries` | 手动 River Memory（人写人读），不参与自动提炼 |
| `memory_lessons` 表 | Node | `storage/memory-lessons.ts` `remember()` | `GET /api/memory/lessons` | **提示词注入**：`routes/groups/groups-chat.ts` 与 `routes/runs/run-sessions/*` 调 `promptBlock()`；run 结束时自动提炼（失败→教训、中断→偏好），零 LLM 调用 |
| `agent_hops` 表 | Node | `storage/memory-handoff.ts`（DAG 每条边一行） | `GET /api/memory/handoff/context`（间接） | 交接审计：`pending → running → done\|failed\|timeout\|empty\|denied\|aborted`，部分索引只索引未结算行 |
| `memory_handoffs` 表 | Node | `storage/memory-handoff.ts` `createHandoff()` | `GET /api/memory/handoff/...` | 交接包头（summary/status/context_json），幂等键 `UNIQUE(shift_id, from_agent, to_agent)` |
| `memory_handoff_items` 表 | Node | 同上 | 同上 | 交接内容副本（不写回 `memory_lessons`，避免挤占每域 8 条上限） |
| `memory_profile_values` 表 | Node | `storage/memory-handoff.ts` `writeback()` | `GET /api/memory/handoff/profiles/:subjectId` | 长期画像「当前值」表；`storage/evidence.ts` 只读，用于证据看板 |
| `memory_profile_events` 表 | Node | 同上（append-only） | `GET /api/memory/handoff/profiles/conflicts` | 画像变更流水，可回溯/冲突解决（`source='conflict_resolution'` 计数） |
| `memory_context_reads` 表 | Node | `storage/memory-handoff.ts` `contextFor()` | `GET /api/memory/handoff/context/reads` | 交接上下文被读次数与时间窗（观察记忆是否真被用上） |
| `memory_feedback_queue` 表 | Node | 同上 `feedback` 接口 | `GET /api/memory/handoff/feedback` | 人工反馈排队，反哺 lessons 权重 |

**写入口收敛**：`app.sqlite` 的 8 张记忆表，写操作全部收敛在两个模块——`storage/memory-handoff.ts`（`agent_hops` / `memory_handoffs` / `memory_handoff_items` / `memory_profile_values` / `memory_profile_events` / `memory_context_reads` / `memory_feedback_queue`，7 张）与 `storage/memory-lessons.ts`（`memory_lessons`，1 张），各管各的表、无交叉写。`storage/evidence.ts` 对这些表**零写操作**（已 grep 核验：`INSERT/UPDATE/DELETE` 命中 0），只做统计 SELECT。

## 3. Python 侧记忆数据

| 数据（表/文件） | 归属进程 | 写者（唯一） | 读端点 | 消费方 |
|---|---|---|---|---|
| `.shadowflow/knowledge/<pack_id>/memory_bank.sqlite`（meta / sources / parents / units / chunks / chunks_fts / links） | Python | `memory/memory_bank.py`（每 pack 一库，`PRAGMA user_version=1`） | `/api/memory-bank/packs/...`（列表/摄入/查询/删除） | RAG executor（`runtime/executors.py`）、`eval_service`、目录摄入；Node 侧经 `lib/memory-bank.ts` 走 HTTP 查询 |
| `chunks_fts`（FTS5 虚表） | Python | 同上（随 chunks 写入重建） | 同上 | 关键词召回，与向量召回融合 |
| 打包清单 `manifest` / pack 目录 | Python | `memory_bank.py`（`_verify_manifest` 校验 `schema=shadowflow.memory_bank/1`） | 同上 | 导入/导出 pack 时的一致性校验 |
| `MemoryProfile` 对象（`api/memory/memory.py` 的进程内 `_profiles` 字典） | Python | `POST /api/memory/profiles` | `GET /api/memory/profiles`、`/api/memory/stats`、`/api/memory/state/{agent_id}` | `runtime/context_builder.py` 的压缩策略 / 写回策略 |
| 写回执行 `POST /api/memory/writeback/{run_id}` | Python | 该端点（按 policy 触发） | — | 把 run 产出写回上下文/memory 目标 |
| `runtime/memory_bridge/`（外部记忆桥 + 熔断器） | Python | `bridge.py`（`pour`/反馈） | 无独立 REST，挂在 Hermes 网关内部 | `runtime/gateway/hermes.py`：向外部记忆服务灌注/回捞，熔断事件落 `agent.memory_bridge_circuit_*` |

> `MemoryProfile` 的 `_profiles` 是**进程内字典，无持久化**：重启即失。它只承载「本次运行的压缩/写回策略」，不是长期记忆数据——长期画像在 Node 的 `memory_profile_values`。这条边界写在这里，避免有人误以为 Python 也存了一份画像。

## 4. memory_handoff 数据流（Agent A → Agent B）

```
groups-chat.ts 每回合结束
   └─ buildRoundHandoffPayload(input)            // 组装：上一跳产出摘要 + 相关 lessons + 画像值
        └─ findHandoffByShift(shift_id)           // 幂等锚：同回合已有包 → 直接返回
             └─ createHandoff(payload)            // 写 memory_handoffs + memory_handoff_items
                  │  status = 'pending'
                  ↓
Agent B 启动 / 被派活
   └─ contextFor(to_agent, scope_key, task_type)  // 读 memory_handoffs(status=pending) + items
        └─ 写 memory_context_reads（读行为留痕：谁在什么时候读了哪份交接）
             └─ acceptHandoff(id, to_agent)       // status → 'accepted'，记 accepted_at
                  ↓
Agent B 跑完 / 超时 / 被拒
   └─ agent_hops 该边结算（done|failed|timeout|empty|denied|aborted, settled_at）
        └─ writeback()                            // 把新得出的画像值写 memory_profile_values + events
             └─ 经验进 memory_lessons（同域上限 8 条，重复只加权）
                  ↓
人工在对话里反馈
   └─ POST /api/memory/handoff/feedback → memory_feedback_queue → 反哺 lessons 权重
```

关键点：

- **幂等**：`shift_id` 是回合锚，`UNIQUE(shift_id, from_agent, to_agent)` 保证同一回合不会重复建包。
- **失败不阻塞主链路**：`createHandoff` 外层整体 `.catch()`，SQLite 不可用时静默跳过（聊天优先）。
- **审计与内容分离**：`agent_hops` 只放状态流水（小、可索引）；内容副本在 `memory_handoff_items`（大、按 handoff_id 索引）。
- **全链路在 Node 内**：不跨进程，不读 Python 库。

## 5. 曾存在的双写点与处置

| 双写点 | 现状 | 处置 |
|---|---|---|
| `memory_profile_values/events` 由 `evidence.ts` 与 `memory-handoff.ts` 同时引用 | `evidence.ts` 只有 SELECT/GROUP BY（证据看板统计），**无写操作** | 无需改代码；本文件将其固化为「唯一写者 = `memory-handoff.writeback()`」，后续新增统计页一律只读 |
| Python `MemoryProfile._profiles`（进程内）与 Node `memory_profile_values`（持久化）概念重名 | 两者语义不同：前者是本次运行的策略对象，后者是长期画像 | 已在 §3 明确边界；不合并，避免把策略对象持久化后污染画像域 |
| 多模态记忆库（Python RAG）与 River Memory（Node JSON）都能被用户「加知识」 | 数据面完全隔离：pack 目录 vs 单 JSON 文件；入口分别是 `/api/memory-bank/*` 与 `/api/memory-entries` | 保持隔离。前端需在 UI 上区分「知识库（RAG）」与「记忆条目（River）」，勿混叫「记忆库」 |
| 旧 agentgraph 记忆栈（`memory/sqlite.py`、`user.py`、`global_memory.py`、`patterns.py`、`layers.py`、`session.py`、`redis.py`） | 依赖外部 `agentgraph` 包，仅 `shadowflow/memory/__init__.py` 函数内延迟 import；**运行链路未使用** | 标记「历史遗留，勿新增引用」，后续清理批次统一下线；本次不动（`memory/sqlite.py.bak` 亦为残留） |
