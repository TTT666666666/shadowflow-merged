# 宣称-证据对账（2026-11）

## 1. 它解决的问题

商品诊断回答「这句话会不会被平台判违规」。对账回答另一件事：**这句话你有没有资格说。**

| 问题 | 谁能答 |
|---|---|
| 「100%纯棉」是不是违禁词 | 词表 / 小模型都行 |
| 「100%纯棉」你有没有检测报告 | 只有对账能答 |
| 报告过期了吗 | 只有对账能答 |
| 报告是上家的公司名，不是你的 | 只有对账能答 |
| 报告写「棉针织」，你卖的是真丝 | 只有对账能答 |

前四行里，只有第一行是「理解」问题，后四行是**台账对账**问题。这是本功能的全部立意。

## 2. 为什么小模型蒸馏替代不了这一段

用户在考虑蒸馏小模型。这件事要分两层看，两层结论相反：

**可以蒸馏、也应该蒸馏的：**
- 宣称抽取（文本 → 这是成分宣称 / 认证宣称 / 功效宣称）
- 违禁词变体识别（「最~好」「zui低价」「美白祛斑」这类改写）

这两层是纯文本任务，小模型微调后比词表更稳、更便宜。**建议蒸馏。**

**不要蒸馏的：**
- 编号格式校验：`国妆特字G` + 8 位、`SC` + 14 位、3C 16 位、`国食健字` + 8 位
- 有效期比较：证书日期 < 今天
- 主体一致性：证书主体 vs 店铺主体
- 证据与宣称的类型匹配：美白→特证，减肥→蓝帽子，3C→CCC

前三条是确定性计算。模型做这三件事的失败方式不是「答错」，是「**编一个看起来对的**」——它会把 7 位的号补成 8 位，因为从上下文看「应该」是 8 位。在合规场景，这种错误比漏判严重得多：漏判是没发现问题，编造是**制造了一份假证据**。

第四条是知识映射，也不难，但它的价值在于**可被法务逐条复核**。规则表可以打印出来给法务签字，模型的判断不能。

所以正确架构是：

```
小模型 / 词表：文本 → 宣称列表        （蒸馏这一层）
规则表：      宣称 + 台账 → 对账结论   （保留这一层）
```

两者互补，不是替代。

## 3. 细到什么程度

| 维度 | 内容 |
|---|---|
| 宣称类型 | 6 类：成分/材质、认证/资质、功效、安全性、参数、售后承诺 |
| 证据类型 | 8 类：检测报告、特殊化妆品注册证、有机认证、3C、食品生产许可、保健食品批号、医疗器械注册证、品牌授权书 |
| 编号格式 | 每类一个正则，正则不匹配直接判 `bad_code` |
| 状态 | 7 种：已覆盖、缺证据、已过期、编号格式不对、证书主体不符、证书范围不覆盖、需人工核验 |
| 判定可信度 | 3 档：`strict`（正则/日期，可直接下结论）、`heuristic`（关键词，只提示）、`manual`（无法自动判定） |

关键设计：**词映射只在认证与功效两类生效。**
「有机棉」是成分宣称，虽然含「有机」，但它要的是成分检测报告，不是有机认证。第一版把词映射套到所有类型上，结果所有有机棉商品都被要求补一张根本不需要的证书——这是实测截图发现的，已修并锁进测试。

同理，多证据类型**不做「任一即可」的宽松匹配**：第一版让「有机」接受 `organic_cert / ccc / test_report` 中的任意一张，导致一份普通检测报告就能冒充有机认证。现在按具体词指定唯一证据类型，宁可判「缺有机认证」，也不拿错证充数。

## 4. 实测

输入：`有机精梳棉男士短袖T恤`，卖点 `100%有机棉面料`，店铺主体 `杭州甲纺织有限公司`，台账里一张 **2021 年过期**的 CMA 报告（范围：棉针织面料）。

| 宣称 | 类型 | 需要的证据 | 状态 |
|---|---|---|---|
| 有机棉 | 成分 / 材质 | 检测报告 | **已过期** |
| 有机 | 认证 / 资质 | 有机产品认证 | **缺证据** |
| 无理由 | 售后承诺 | 无需资质 | 已覆盖 |

结论：2 条阻塞，`can_claim=false`。

这张表的价值在于它能直接交给甲方：不是「你的文案有问题」，而是「你有 2 条宣称缺证，其中一张证 2021 年就过期了」。

## 5. 已验证的判定（`tests/test_claim_evidence.py`，16 例）

- 缺证据 → `missing`，阻塞
- 有效证据 + 主体一致 + 范围覆盖 → `ok`
- 证书过期 → `expired`
- `国妆特字G2020123`（少一位）→ `bad_code`
- 证书主体 A 公司、店铺主体 B 公司 → `subject_mismatch`
- 证书范围「棉针织」、宣称「真丝」→ `scope_mismatch`
- 售后承诺 → `ok` + `manual`（不需要资质，但要能兑现）
- `CMA 2024-123456`（带分隔符）→ 仍识别为合法编号
- 未填有效期 → `unknown`，**不能当成通过**
- 参数（`60cm`、`20kg`）→ 不阻塞（否则每个尺寸都要质检报告，功能没法用）
- 「有机棉」→ 要检测报告，不要有机认证（反向张冠李戴的回归锁）

## 6. 已知边界

| 边界 | 现状 |
|---|---|
| 范围覆盖 | 关键词/材质字比对，是 `heuristic`，可能误报，标了可信度 |
| 品牌授权书 | 无统一编号格式，只能核有效期和主体 |
| 证书真伪 | **不查真伪**，只查格式。查真伪要对接官方数据库，本轮不做 |
| 一证多品 | 一张报告覆盖多个 SKU 时，需要人工确认范围，不做自动推断 |
| 图片里的资质 | 看不到，需要 OCR 或人工录入 |

最后两条要说清楚：这个功能**不保证证书是真的**，只保证「格式对、没过期、是你的、范围覆盖」。真伪是另一个问题，成本高一个量级。

## 7. 下一步

1. **批量对账**：代运营手里是 200 个 SKU，不是 1 个。把台账做一次、对所有 SKU 跑一遍，输出「哪 37 个 SKU 缺证」——这才是他们愿意付钱的形态。
2. **平台矩阵**：同一张证在亚马逊/TikTok 认不认，是跨境卖家的真需求。
3. **证书文件上传 + OCR**：现在是手填，实际场景是拍一张证书照片。
