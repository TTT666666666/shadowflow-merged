# ShadowFlow 新架构蓝图（v2）

> 2026-11-09 · 就地升级、治理地基优先。本文是后续编码的唯一依据；

## 0. 升级目标

在现有「前端 → Node 网关 → Python 编排核心」三进程架构**之上**构建新架构，
本阶段解决五大治理问题：

| # | 问题 | 目标状态 |
|---|---|---|
| 1 | 端口/URL 三处硬编码口径不一（dev.mjs、vite.config、FRONTEND_ORIGIN 默认值） | **单一配置源 `config/ports.json`**，全部服务从一处读 |
| 2 | 契约三处手抄（contracts.py ↔ lib/contracts.ts ↔ chat-api.ts），修复脚本指向不存在的路径 | **Pydantic 单源 → 自动生成 TS**，check 脚本防漂移 |
| 3 | 上帝文件（ProductApp.tsx 6538 行等） | 按 View/职责拆分，行为不变 |
| 4 | 双栈并存（LLM/BYOK/群存储/DAG/记忆 各两套） | 逐域收敛为单写者（后续阶段） |
| 5 | SQLite 无版本化 migration 框架 | 版本化 migration（后续阶段） |

## 1. 服务端口编排（组装端口 · 网络层）

### 1.1 端口分配表（保持现有端口不变）

| 服务 | 端口 | 进程 | 说明 |
|---|---|---|---|
| 前端 Vite（宣传页 + 董事长工作台） | **8443** | `frontend/` | 浏览器唯一入口；`/api`、`/projects` 代理到网关 |
| Node 网关（API 聚合 + 业务域落库） | **8002** | `backend/node/` | 前端唯一后端入口；未接管的 `/api/*` 兜底转 Python |
| Python 编排核心（shadowflow） | **8000** | `backend/python/` | Agent 运行时 · 任务 DAG · 知识库 |

预留端口段（未来新增服务从这里取，不与上表冲突）：**8010–8019**。

### 1.2 单一配置源

```
config/ports.json        ← 唯一权威来源（web / gateway / python 三个键）
```

读取与覆盖规则（各服务一致）：

```
进程自身 env（PORT / PYTHON_BACKEND_URL / FRONTEND_ORIGIN …）
    > config/ports.json
    > 内置兜底（与 ports.json 默认值相同）
```

各启动/读取路径：

| 消费方 | 读取方式 |
|---|---|
| `dev.mjs` | `scripts/ports.mjs` loader 读 ports.json，逐子进程传 `PORT` 等 env |
| `frontend/vite.config.ts` | fs 读 ports.json：dev 端口 + 代理目标 `http://127.0.0.1:<gateway>` |
| `backend/node/src/config/ports.ts` | Node 侧唯一 loader：导出 `PORTS`，并派生 `PORT` / `PYTHON_BACKEND_URL` / `FRONTEND_ORIGIN` 默认值 |
| `backend/python/shadowflow/port_config.py` | Python 侧唯一 loader：cli serve 默认端口、`__main__` uvicorn 端口、`SF_BASE_URL` / CORS 默认来源 |
| `npm run dev:python` | `scripts/py-serve.mjs` 读 ports.json 后 spawn uvicorn（不再硬编码 8000） |

**FRONTEND_ORIGIN 默认值修正**：旧默认 `http://localhost:3007`（已失效）→
由 web 端口派生 `http://localhost:<web>`（即 8443）。

## 2. 模块组装端口（组装端口 · 契约层）

模块之间只允许通过下列「端口」组装，端口的类型契约单源生成、禁止手抄。

```
┌────────────┐   P1 REST/SSE    ┌────────────┐   P2 HTTP    ┌──────────────┐
│  前端 8443  │ ◀──────────────▶ │ Node 网关   │ ◀──────────▶ │ Python 编排   │
└────────────┘  /api, /projects └────────────┘  PYTHON_URL  └──────────────┘
```

### P1 · 前端 ↔ Node 网关

- 传输：REST + SSE（`/api/*`、`/projects/*`），鉴权 Bearer（游客会话由前端签发）。
- 契约：`frontend/src/generated/sf-contracts.ts`（自动生成）；
  `chat-api.ts` 只做取数封装，**类型从生成文件 import**，不再自定义同名接口。

### P2 · Node 网关 ↔ Python 编排核心

- 传输：HTTP，基准 URL 由 `config/ports.json` 派生（env `PYTHON_BACKEND_URL` 可覆盖）；
  两条通道：proxy-fallback 透明代理（`/api/*` 兜底）+ 业务直调（群持久化、memory-bank、loops 等）。
- 隐式协议头（现状保留，后续收敛为公开 API 语义）：`X-SF-No-Dispatch` 等 `X-SF-*`。
- 契约：`backend/node/src/generated/sf-contracts.ts`（与前端同一份生成器产出）；
  `lib/contracts.ts` 仅保留 Node 侧扩展类型，公共类型从生成文件 re-export。

### P3 · Python 编排核心内部（模块边界）

| 端口 | 提供方 → 消费方 | 契约 |
|---|---|---|
| 执行端口 | `RuntimeService` → `executors.py`（AgentTeams/Cli/Api/Rag） | `runtime/contracts.py`（Pydantic，**契约唯一源头**） |
| 装配端口 | `assembly/compile.py` → `WorkflowDefinition` | `WorkflowAssemblySpec` |
| 记忆端口 | `memory/memory_bank.py`（RAG）← api 层 | pack/source/chunk 查询协议 |

### P4 · 存储端口（单写者规则）

| 数据 | 唯一写者 | 文件 |
|---|---|---|
| run 记录 / 群消息（默认）/ 记忆 / craft 业务域 / token 用量 / 用户 | **Node** | `.shadowflow/app.sqlite` |
| 群消息持久化（默认 `SF_GROUPS_BACKEND=python`） | **Python** | `.shadowflow/groups/*.json` |
| 运行时事件 / 检查点 | **Python** | `.shadowflow/runtime.sqlite` |
| 知识库（RAG） | **Python** | `.shadowflow/knowledge/*/*.sqlite` |
| BYOK / 设置 | **Node**（`settings.json`）| 后续阶段收敛：Python 侧读同一份 |

> 同一份数据不允许两个进程写。`SF_GROUPS_BACKEND` 双轨是过渡态，收敛列入后续阶段。

### 契约生成管线（防漂移）

跨进程契约分两个家族，各有唯一源头与漂移防护，**手抄类型一律视为 bug**：

**① 运行时契约（Python 源）**——workflow/run/loop/checkpoint 域：

```
backend/python/shadowflow/runtime/contracts.py   ← 唯一契约源头（Pydantic v2）
        │  python scripts/generate_ts_types.py
        ├─▶ backend/node/src/generated/sf-contracts.ts   （AUTO-GENERATED）
        └─▶ frontend/src/generated/sf-contracts.ts      （AUTO-GENERATED）
        校验：python scripts/check_contracts.py（字节级比对，任一漂移 → exit 1）
```

**② 时间线契约（Node 源）**——TimelineMessage/MessagePatch 聊天流契约：

```
backend/node/src/lib/contracts.ts   ← 唯一源头
        └─▶ frontend/src/chat-api.ts（子集 + 前端自有 API 类型）
        校验：check_contracts.py 对子集做名称级比对（新增/改名未同步 → exit 1）
```

规则：
1. 新增跨进程字段只改唯一源头再重新生成/同步，禁止在消费侧私自加同名类型。
2. 提交前跑 `npm run contracts:check`；CI 应挂同一命令（后续接入）。
3. 生成文件头部带 `AUTO-GENERATED — DO NOT EDIT`，不进人工 review 的改动面。

## 3. 目标目录形态（治理后）

```
config/ports.json                  端口单一配置源
scripts/ports.mjs                  Node 侧 loader（dev.mjs / py-serve.mjs 共用）
scripts/py-serve.mjs               分步启动 Python（读 ports.json）
scripts/generate_ts_types.py       契约生成（双产物）
scripts/check_contracts.py         契约漂移校验（双产物 + 前端密钥扫描）

backend/node/src/generated/        生成契约（勿手改）
backend/python/shadowflow/port_config.py   Python 侧端口 loader（唯一）
frontend/src/generated/            生成契约（勿手改）
frontend/src/views/                ProductApp 拆分后的各视图（阶段2）
```
